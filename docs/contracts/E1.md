# hookrelay — E1 Contract: Endpoints & data model

Read together with [`docs/CONTRACT.md`](../CONTRACT.md) (versions, ports, env vars,
commands, git conventions). Where they differ, this file wins for E1.

## 1. Goal and scope

At the end of E1 a client can:

1. Register, list, read, update and delete **endpoints** (subscriber URLs, each
   subscribed to one or more event types).
2. Submit **events**. Each event is stored durably, idempotently, and fanned out
   into one **delivery** record (status `PENDING`) per matching endpoint, in the
   same database transaction.
3. Query events and deliveries.

**Out of scope (later milestones):** actually sending HTTP requests to endpoints
and publishing to RabbitMQ (E2), retries/backoff/DLQ logic (E3), request signing,
secret rotation and API authentication (E4), metrics/tracing (E5), replay/admin
(E6), rate limits and payload size limits (E7). Do not add RabbitMQ queues,
listeners or HTTP clients in E1.

## 2. Packages (package-by-feature)

Base package `io.github.joseferrao20.hookrelay`:

| Package | Contents |
|---------|----------|
| `endpoint` | `Endpoint` (entity), `EndpointRepository`, `EndpointService`, `EndpointController`, DTO records |
| `event` | `Event` (entity), `EventRepository`, `EventService`, `EventController`, DTO records |
| `delivery` | `Delivery` (entity), `DeliveryStatus` (enum), `DeliveryRepository`, `DeliveryService`, `DeliveryController`, DTO records |
| `common` | `NotFoundException`, `ConflictException`, `GlobalExceptionHandler` (`@RestControllerAdvice`), `PageResponse<T>` |
| `config` | `ClockConfig` (`Clock` bean, UTC), `OpenApiConfig` |

Rules:
- Controllers only talk to services; services own transactions (`@Transactional`).
- DTOs are Java `record`s; entities are never serialized directly.
- Entities get their `UUID` id in the constructor (`UUID.randomUUID()`), not via
  `@GeneratedValue`. Timestamps come from the injected `Clock`.
- Constructor injection only; no field injection, no Lombok.

## 3. Database schema (Flyway)

Single migration `src/main/resources/db/migration/V1__initial_schema.sql`, exactly:

```sql
CREATE TABLE endpoints (
    id          UUID PRIMARY KEY,
    url         VARCHAR(2048) NOT NULL,
    description VARCHAR(500),
    secret      VARCHAR(100)  NOT NULL,
    enabled     BOOLEAN       NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ   NOT NULL,
    updated_at  TIMESTAMPTZ   NOT NULL,
    deleted_at  TIMESTAMPTZ
);

CREATE TABLE endpoint_event_types (
    endpoint_id UUID         NOT NULL REFERENCES endpoints (id) ON DELETE CASCADE,
    event_type  VARCHAR(100) NOT NULL,
    PRIMARY KEY (endpoint_id, event_type)
);

CREATE INDEX idx_endpoint_event_types_type ON endpoint_event_types (event_type);

CREATE TABLE events (
    id              UUID PRIMARY KEY,
    event_type      VARCHAR(100) NOT NULL,
    payload         JSONB        NOT NULL,
    idempotency_key VARCHAR(255),
    created_at      TIMESTAMPTZ  NOT NULL,
    CONSTRAINT uq_events_idempotency_key UNIQUE (idempotency_key)
);

CREATE INDEX idx_events_type_created ON events (event_type, created_at DESC);
CREATE INDEX idx_events_created ON events (created_at DESC);

CREATE TABLE deliveries (
    id                   UUID PRIMARY KEY,
    event_id             UUID        NOT NULL REFERENCES events (id),
    endpoint_id          UUID        NOT NULL REFERENCES endpoints (id),
    status               VARCHAR(20) NOT NULL,
    attempt_count        INTEGER     NOT NULL DEFAULT 0,
    next_attempt_at      TIMESTAMPTZ,
    last_attempt_at      TIMESTAMPTZ,
    last_response_status INTEGER,
    last_error           VARCHAR(2000),
    created_at           TIMESTAMPTZ NOT NULL,
    updated_at           TIMESTAMPTZ NOT NULL,
    version              BIGINT      NOT NULL DEFAULT 0,
    CONSTRAINT uq_deliveries_event_endpoint UNIQUE (event_id, endpoint_id),
    CONSTRAINT ck_deliveries_status
        CHECK (status IN ('PENDING', 'SUCCEEDED', 'FAILED', 'DEAD'))
);

CREATE INDEX idx_deliveries_status_next_attempt ON deliveries (status, next_attempt_at);
CREATE INDEX idx_deliveries_endpoint_created ON deliveries (endpoint_id, created_at DESC);
CREATE INDEX idx_deliveries_event ON deliveries (event_id);
```

Mapping notes:
- `ddl-auto: validate` stays on; entities must validate against this schema.
- `endpoint_event_types` → `@ElementCollection Set<String> eventTypes` on `Endpoint`.
- `events.payload` → Jackson `JsonNode` with `@JdbcTypeCode(SqlTypes.JSON)`.
- `deliveries.status` → `@Enumerated(EnumType.STRING) DeliveryStatus`.
- `deliveries.version` → `@Version`.
- Soft delete: `endpoints.deleted_at`. Deleted endpoints are invisible to the API
  (404) and never receive new deliveries; existing deliveries keep the FK.

Domain semantics:
- `DeliveryStatus`: `PENDING` (waiting for an attempt), `SUCCEEDED`, `FAILED`
  (last attempt failed, will be retried), `DEAD` (gave up). E1 only creates
  `PENDING`, with `attempt_count = 0` and `next_attempt_at = created_at`.
- Event type format: `^[A-Za-z0-9._-]{1,100}$` (e.g. `order.created`).
- An endpoint subscribes to a non-empty set of event types; the special value
  `*` means "all event types".
- **Fan-out rule:** on event creation, create one `PENDING` delivery for every
  endpoint where `enabled = true AND deleted_at IS NULL AND (event_types contains
  the event's type OR contains '*')`.
- Endpoint secret: generated server-side on create as `whsec_` + 32 bytes from
  `SecureRandom`, Base64 URL-encoded without padding. Stored as is (signing in E4
  needs it). Returned **only** in the create response.

## 4. REST API

Base path `/api/v1`. JSON (`application/json`), timestamps ISO-8601 UTC
(`Instant`), ids UUID strings. No authentication in E1.

### 4.1 Endpoints

| Method & path | Request | Success |
|---------------|---------|---------|
| `POST /api/v1/endpoints` | `CreateEndpointRequest` | `201`, `Location: /api/v1/endpoints/{id}`, `EndpointCreatedResponse` |
| `GET /api/v1/endpoints?page=0&size=20` | – | `200`, `PageResponse<EndpointResponse>` (excludes deleted, newest first) |
| `GET /api/v1/endpoints/{id}` | – | `200`, `EndpointResponse` |
| `PATCH /api/v1/endpoints/{id}` | `UpdateEndpointRequest` | `200`, `EndpointResponse` |
| `DELETE /api/v1/endpoints/{id}` | – | `204` (soft delete) |

```jsonc
// CreateEndpointRequest
{
  "url": "https://example.com/webhooks",   // required, absolute http/https URL, ≤ 2048 chars
  "description": "Orders service",          // optional, ≤ 500 chars
  "eventTypes": ["order.created", "order.paid"], // required, 1..50 items, each "*" or event type format
  "enabled": true                            // optional, default true
}
// UpdateEndpointRequest: same fields, all optional; null/absent = unchanged.
// Same validation when present; eventTypes, when present, replaces the whole set.

// EndpointResponse
{
  "id": "…", "url": "…", "description": "…",
  "eventTypes": ["order.created", "order.paid"],   // sorted ascending
  "enabled": true,
  "createdAt": "2026-11-18T15:00:00Z", "updatedAt": "2026-11-18T15:00:00Z"
}
// EndpointCreatedResponse = EndpointResponse fields + "secret": "whsec_…"
```

### 4.2 Events

| Method & path | Request | Success |
|---------------|---------|---------|
| `POST /api/v1/events` | header `Idempotency-Key` (optional, 1..255 chars) + `CreateEventRequest` | new: `202`, `Location: /api/v1/events/{id}`, `EventResponse`; replay: `200`, same `EventResponse` |
| `GET /api/v1/events?eventType=&page=0&size=20` | – | `200`, `PageResponse<EventSummaryResponse>` (newest first) |
| `GET /api/v1/events/{id}` | – | `200`, `EventResponse` |

```jsonc
// CreateEventRequest
{
  "eventType": "order.created",   // required, event type format ("*" not allowed)
  "payload": { "orderId": 42 }    // required, must be a JSON object
}

// EventResponse
{
  "id": "…", "eventType": "order.created", "payload": { "orderId": 42 },
  "idempotencyKey": "abc-123",    // null when not provided
  "createdAt": "…",
  "deliveries": [ { "id": "…", "endpointId": "…", "status": "PENDING" } ]
}

// EventSummaryResponse
{ "id": "…", "eventType": "…", "idempotencyKey": null, "createdAt": "…" }
```

Idempotency:
- Same `Idempotency-Key` with the same `eventType` and `payload` (JSON-equal) →
  `200` with the original event; no new deliveries.
- Same key with a different `eventType` or `payload` → `409`.
- Concurrent requests with the same key: the unique constraint decides; the loser
  re-reads and answers as a replay (`200`) or `409`.

### 4.3 Deliveries (read-only)

| Method & path | Success |
|---------------|---------|
| `GET /api/v1/deliveries?eventId=&endpointId=&status=&page=0&size=20` | `200`, `PageResponse<DeliveryResponse>` (filters optional, combinable, newest first) |
| `GET /api/v1/deliveries/{id}` | `200`, `DeliveryResponse` |

```jsonc
// DeliveryResponse
{
  "id": "…", "eventId": "…", "endpointId": "…", "status": "PENDING",
  "attemptCount": 0, "nextAttemptAt": "…", "lastAttemptAt": null,
  "lastResponseStatus": null, "lastError": null,
  "createdAt": "…", "updatedAt": "…"
}
```

### 4.4 Pagination

`page` ≥ 0 (default 0), `size` 1..100 (default 20); out of range → `400`.

```jsonc
// PageResponse<T>
{ "content": [ … ], "page": 0, "size": 20, "totalElements": 1, "totalPages": 1 }
```

### 4.5 Errors

All errors are RFC 9457 Problem Details (`application/problem+json`, Spring
`ProblemDetail`), with `type` left as `about:blank`, plus `title`, `status`,
`detail`, `instance`.

| Situation | Status |
|-----------|--------|
| Bean validation failure | `400`, extra property `errors: [{"field": "url", "message": "…"}]` |
| Malformed JSON, payload not an object, bad UUID/enum/query param | `400` |
| Unknown or soft-deleted resource | `404` |
| Idempotency key reused with different content | `409` |
| Unexpected error | `500` (no stack trace or internal message in the body) |

## 6. Smoke test (local-infra)

`scripts/smoke-test.sh [BASE_URL]` (default `http://localhost:8080`), bash with
`set -euo pipefail`, needs `curl` and `jq` (fail fast with a clear message if
missing). It assumes the app and its dependencies are already running and:

1. waits up to 60 s for `GET /actuator/health` → `"status":"UP"`;
2. creates an endpoint for `smoke.test` and checks `201` + `secret` present;
3. posts a `smoke.test` event with a random `Idempotency-Key` → `202` and
   exactly one delivery for that endpoint with status `PENDING`;
4. re-posts the same request → `200` and the same event id;
5. reads the delivery via `GET /api/v1/deliveries?eventId=…`;
6. deletes the endpoint → `204`, then `GET` → `404`;
7. prints `SMOKE TEST PASSED` and exits `0`; on any failure prints which step
   failed and exits non-zero.

Makefile targets: `run` (`./gradlew bootRun`), `smoke` (runs the script),
`build` (`./gradlew build`), `format` (`./gradlew spotlessApply`).
