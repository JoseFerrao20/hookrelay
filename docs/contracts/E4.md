# hookrelay — E4 Contract: Signing & security

Read together with [`docs/CONTRACT.md`](../CONTRACT.md) and the E1–E3 contracts.
Where they differ, this file wins for E4.

## 1. Goal and scope

At the end of E4:

1. Every webhook is **signed** (HMAC-SHA256) so receivers can verify that it came
   from hookrelay and was not altered or replayed.
2. Endpoint secrets can be **rotated** with a grace period during which both the
   old and the new secret sign.
3. Endpoint secrets are **encrypted at rest** (AES-256-GCM).
4. hookrelay refuses to send to **private/internal addresses (SSRF protection)**,
   both when an endpoint is saved and at connection time, which also guards
   against DNS rebinding.
5. The REST API requires an **API key**.

**Out of scope:** multi-tenant authorization, DB-managed API keys and a key
management API, encryption-key rotation (the `v1:` prefix leaves room for it),
rate limiting and payload size limits (E7), metrics (E5).

## 2. Webhook signatures

- **Signed content** is three parts joined with `.`:
  `<deliveryId>.<timestamp>.<body>`
  - `deliveryId` is the `Hookrelay-Delivery-Id` value.
  - `timestamp` is the `Hookrelay-Timestamp` value (Unix seconds, the same
    number as the header).
  - `body` is the **exact bytes** sent. Serialize the payload to UTF-8 bytes
    once, sign those bytes, and send the same bytes (`byte[]` body).
- **Signature** = Base64 (standard, padded) of `HMAC-SHA256(key, signedContent)`.
  `key` is the UTF-8 bytes of the full secret string, including the `whsec_`
  prefix.
- **Header:** `Hookrelay-Signature: v1=<sig>`. While a rotation grace period is
  active the header carries two entries separated by one space:
  `v1=<sigNewSecret> v1=<sigPreviousSecret>`, with the current secret first.
- A public `WebhookSignature` utility in `dispatch` does both jobs:
  - `sign(secret, deliveryId, timestamp, body)`;
  - `verify(secrets, header, deliveryId, timestamp, body, now, tolerance)`, which
    compares in constant time and rejects timestamps outside the tolerance
    (default 5 min).

  Tests and the docs' receiver guide rely on it.

## 3. Secret rotation

- `POST /api/v1/endpoints/{id}/secret/rotate`
  - Optional body: `{"graceSeconds": 86400}`, range 0..604800, default 86400.
  - Response `200`:
    `{"secret": "whsec_…", "previousSecretExpiresAt": "<instant>" | null}`.
  - The new secret is returned only here.
  - The current secret becomes `previous_secret`, expiring at
    `now + graceSeconds`. With `graceSeconds = 0` the previous secret is cleared
    immediately.
  - Rotating again during a grace period replaces the previous secret with the
    one that was current.
  - `404` for an unknown or soft-deleted endpoint.
- The sender signs with the previous secret only while
  `previous_secret_expires_at > now`. Expired previous secrets are ignored; they
  may stay in the row.

## 4. Encryption at rest

- `secret` and `previous_secret` are stored as `v1:<base64(nonce12 ‖ ciphertext ‖ tag16)>`
  using AES-256-GCM, a random 12-byte nonce per value, and the endpoint id as
  AAD (UTF-8 bytes of the UUID string).
- **Key:** `hookrelay.security.secret-encryption-key`, Base64 of exactly 32
  bytes. The app **fails to start** with a clear message if it is missing or
  malformed.
- `SecretCipher` (in `endpoint` or `common`) does `encrypt(endpointId, plaintext)`
  and `decrypt(endpointId, stored)`. Entities hold ciphertext. Services decrypt
  only when they need the plaintext: create and rotate responses, and signing.
- **Backfill:** an `ApplicationRunner` encrypts any `secret` or `previous_secret`
  that does not start with `v1:` (rows from E1–E3). It is idempotent and safe
  with several instances: use a conditional `UPDATE … WHERE id = ? AND secret = ?`.
  Log the number of rows encrypted at INFO when it is greater than zero.

## 5. SSRF protection

- **Blocked destinations:**
  - loopback (`127.0.0.0/8`, `::1`) and unspecified (`0.0.0.0/8`, `::`);
  - private ranges (`10/8`, `172.16/12`, `192.168/16`, `fc00::/7`);
  - link-local (`169.254/16`, which includes cloud metadata, and `fe80::/10`);
  - CGNAT (`100.64/10`), multicast and broadcast;
  - IPv4-mapped or compatible IPv6 forms of any of these;
  - the hostname `localhost`, and anything ending in `.localhost`.
- **Config** (`hookrelay.security.ssrf`):
  - `allow-private-networks` (default `false`);
  - `allowed-hosts` (list, default empty). Exact, case-insensitive hostnames
    listed here skip the check. Local compose uses `webhook-sink`.
- **On save** (create/PATCH url):
  - reject literal IPs and `localhost` names in blocked ranges;
  - reject hostnames that **resolve** to any blocked address;
  - accept hostnames that do not resolve (yet). The send-time check is the real
    guard.
  - Rejection is a `400` Problem Detail on field `url` with the message
    `must not target a private, loopback or link-local address`.
- **At send time:**
  - Switch `WebhookSender` to **Apache HttpClient 5** (BOM-managed
    `org.apache.httpcomponents.client5:httpclient5`) through
    `HttpComponentsClientHttpRequestFactory`.
  - Use a custom `DnsResolver` that resolves the host and throws if any address
    is blocked. The connection then only ever uses checked addresses, which
    defeats DNS rebinding.
  - Literal-IP URLs must be checked too; test this.
  - Keep E2 behaviour: connect timeout, response timeout, no redirects, response
    body read and discarded.
- **Outcome of a blocked send:** `SendResult` gets a `blockedReason`. The worker
  records an attempt (outcome `FAILED`, no status, the error text) and the
  delivery goes **`DEAD`** with
  `last_error = "Blocked destination: <host> resolves to <ip>"`. It is never
  retried.

## 6. API authentication

- Add `spring-boot-starter-security`. Make it stateless, with CSRF disabled and
  no sessions or form login.
- Clients send `Authorization: Bearer <api-key>`.
- **Config:** `hookrelay.security.api-keys`, a list where each key is at least
  32 characters.
  - The app fails to start if the list is empty.
  - Keys are kept in memory only as SHA-256 digests and compared with
    `MessageDigest.isEqual`.
- **Public paths:** `/actuator/health/**`, `/actuator/info`, `/v3/api-docs/**`,
  `/swagger-ui/**` and `/swagger-ui.html`. **Everything else requires a valid
  key.**
- A missing or invalid key returns `401` with `WWW-Authenticate: Bearer` and a
  Problem Details body (`application/problem+json`, title `Unauthorized`, detail
  `Missing or invalid API key`). The body never echoes the key.
- OpenAPI declares a bearer security scheme so Swagger UI can send the key.

## 7. Schema (Flyway `V4__security.sql`, exactly)

```sql
ALTER TABLE endpoints ALTER COLUMN secret TYPE VARCHAR(255);
ALTER TABLE endpoints ADD COLUMN previous_secret VARCHAR(255);
ALTER TABLE endpoints ADD COLUMN previous_secret_expires_at TIMESTAMPTZ;
```

## 9. Tests (app)

- **Shared test setup** sets an API key, a fixed encryption key and
  `allow-private-networks=true`, because WireMock runs on localhost.
  - Every MockMvc and TestRestTemplate call sends the key.
  - Keep a small helper so tests stay readable.
- **Unit tests:**
  - `WebhookSignature`: a known-answer vector (fixed secret, id, timestamp and
    body give a fixed signature), verify with one or two signatures, tampered
    body, expired timestamp;
  - `SecretCipher`: round trip, wrong AAD fails, tampered ciphertext fails, bad
    key length rejected at startup;
  - SSRF address classifier: every range in §5, IPv4-mapped IPv6, allowed-hosts
    bypass.
- **Integration tests:**
  - **Signing:** a webhook received by WireMock carries `Hookrelay-Signature`,
    and it verifies against the secret returned on create over the exact
    received body.
  - **Rotation:** after a rotation the next webhook has two signatures that
    verify with the new and old secrets. With `graceSeconds = 0` it has one.
    Rotating an unknown endpoint gives `404`.
  - **Encryption:** the DB column holds `v1:…` and never the plaintext. The
    backfill encrypts a plaintext row inserted with SQL.
  - **Auth:**
    - no key or a wrong key gives `401` with Problem Details and
      `WWW-Authenticate`;
    - a valid key gives `200`;
    - health and api-docs are public.
  - **SSRF:** with `allow-private-networks=false`,
    - creating `http://127.0.0.1/x`, `http://169.254.169.254/latest` or
      `http://localhost/x` gives `400` on `url`;
    - an endpoint inserted with SQL that points at `127.0.0.1` makes the
      delivery go `DEAD` with `Blocked destination…` and sends no request;
    - an allowed-hosts entry bypasses the check.
- Update existing tests for the new HTTP client where error texts changed. Keep
  the assertions meaningful and do not loosen them to `isNotBlank` unless the
  text is genuinely platform-dependent.
- `./gradlew build` stays green.

## 10. Local infra and smoke test (local-infra)

- **Compose `app` env, passed through with dev defaults:**
  - `HOOKRELAY_SECURITY_API_KEYS` defaults to
    `${HOOKRELAY_SECURITY_API_KEYS:-dev-only-api-key-change-me-0123456789}`;
  - `HOOKRELAY_SECURITY_SECRET_ENCRYPTION_KEY` defaults to a fixed dev Base64
    32-byte key; generate it once and write it in the file;
  - `HOOKRELAY_SECURITY_SSRF_ALLOWED_HOSTS` defaults to `webhook-sink`.
  - Put the same values in `.env.example` under a
    `# DEV ONLY — never use in production` comment, together with the commands
    to generate real values (`openssl rand -base64 32`).
- **`scripts/smoke-test.sh`:**
  - It reads `HOOKRELAY_API_KEY`, defaulting to the dev key above, and sends
    `Authorization: Bearer …` on every API call.
  - It keeps all E3 steps and adds:
    1. `GET /api/v1/endpoints` without a key returns `401`. Run this right after
       the health wait.
    2. **Signature check**, right after the "sink received the webhook" step:
       recompute `base64(HMAC-SHA256(secret, "<deliveryId>.<timestamp>.<body>"))`
       with `openssl dgst -sha256 -hmac "$SECRET" -binary | base64`. Use the
       secret from the create response and the exact body and headers the sink
       recorded. Assert it appears in `Hookrelay-Signature`.
    3. **Rotation:** rotate the main endpoint's secret with the default grace
       period, post another event, and wait for `SUCCEEDED`. Assert the new
       webhook's `Hookrelay-Signature` has two `v1=` entries, matching the new
       and the old secret.
    4. **SSRF:** creating an endpoint with URL `http://169.254.169.254/latest`
       returns `400`.
  - `openssl` becomes a required tool. Fail fast with exit `2` if it is missing,
    like `curl` and `jq`.
  - The sink must record the body **exactly as received** (raw bytes), so the
    signature can be recomputed. Check `webhook-sink.py` keeps the raw body; if
    it does not, store it base64-encoded as `body_b64`.
- **Makefile:** no changes needed beyond what the env defaults give.
  `make smoke` must work right after `make up-all`.

## 11. CI and docs (ci-docs)

- **CI:** no workflow changes are expected, because compose defaults make CI
  work. If the smoke job needs `openssl`, it is on the Ubuntu runners.
- **`.github/dependabot.yml`:** ignore `version-update:semver-major` for
  `org.springframework.boot`, `io.spring.dependency-management`,
  `org.springdoc:springdoc-openapi-starter-webmvc-ui`, `gradle-wrapper` and the
  docker image `eclipse-temurin`. The contract pins Spring Boot 3.x and Java 21;
  majors are a deliberate decision. Add a comment saying so.
- **`docs/adr/0005-security.md`** covers:
  - a short threat model (forged or replayed webhooks, leaked DB dump, SSRF to
    internal services or metadata, unauthenticated API use);
  - the signature scheme and why the delivery id and timestamp are signed;
  - rotation with dual signatures;
  - AES-GCM with the endpoint id as AAD, and key handling;
  - SSRF checked on save and at connect time through a custom resolver (DNS
    rebinding), and why the HTTP client moved to Apache HttpClient 5;
  - config-based API keys and their limits (no scopes, no per-key revocation
    without a redeploy). E6/E7 follow-ups.
- **`README.md`:**
  - an **Authentication** section; every `curl` example gets
    `-H "Authorization: Bearer $HOOKRELAY_API_KEY"`;
  - a **Verifying webhooks** guide for receivers: the exact algorithm, a
    Python 3 stdlib example (`hmac.compare_digest`, 5-minute tolerance, accept
    any `v1=` entry) and the `openssl` one-liner;
  - a **Rotating secrets** section;
  - the security config table from §8;
  - an SSRF note about allowed-hosts for local development;
  - E4 marked current in the roadmap.
